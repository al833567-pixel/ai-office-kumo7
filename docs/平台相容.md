# 平台相容與接法

所有平台共用同一個 Office Hub。每個平台可以扮演三種角色，接法各不相同：

| 角色 | 做什麼 | 需要的條件 |
|---|---|---|
| **櫃台** | 你在這裡下目標、收最後結果 | 能呼叫 Hub 的 MCP 工具（`office_new_goal`、`office_wait`），或能執行 `office ask` 指令 |
| **主管** | 拆任務、派工、收回報、審查、結案 | Claude Code：終端機版靠 channels 被即時叫醒；桌面版在同一輪裡用 `office_wait` 等回報 |
| **執行者** | 接一個任務、做完、回報 | 有「給提示詞、跑完就結束」的命令列模式，由 office-node 代為收發 |

## 一、加帳號

每個 agent 各需要一個帳號。最簡單是在那台電腦執行 `office join`，網頁上按確認，token 會自動寫進設定檔：

```bash
office join http://<Hub>:7070 --kind codex
```

也可以在 Hub 那台手動建立，再把印出的 token 填進那台機器的設定檔：

```bash
bun run cli add codex_a --name Codex-A --kind codex --machine A
```

`--kind` 決定畫面上的造型和分工建議，可用的值：`claude`、`hermes`、`codex`、`antigravity`、`other`。電腦名稱 `office join` 會自動帶入（手動建立時用 `--machine` 填）。一台電腦可以有很多個 agent，十台電腦各一個也可以。之後可以在網頁右上角「成員」改名、寫說明、停用或刪除。

辦公室畫面最多 8 個工位，依「機器 → 種類 → 建立順序」分配。一台 8 個、8 台各 1 個或任何組合都可以；第 9 個以後的帳號仍然能派工、聊天，只是不會出現在辦公室畫面。

## 二、當執行者（office-node 代為收發）

在那台機器的 `~/.office/config.json` 的 `workers` 陣列加一段。一台可以同時接多個，每個各自一條迴圈。範本都在 `node/config.workers.example.json`。

指令裡可用的佔位字：

| 佔位字 | 換成 |
|---|---|
| `{prompt_file}` | 提示詞寫成的暫存檔路徑（跑完自動刪除） |
| `{answer_file}` | 這個任務的 `answer.md`：執行者把「給主管的結論」寫在這裡，回報只送這份 |
| `{cwd}` | 任務工作目錄 |
| `{out_dir}` | 交付檔案的資料夾（裡面的檔案會自動上傳） |

沒有用 `{prompt_file}` 時，`prompt_via` 決定提示詞怎麼給：`arg`（最後一個參數，預設）、`file`（寫成檔案，最後一個參數放路徑）、`stdin`（從標準輸入給）。

| 平台 | 建議設定 | 說明 |
|---|---|---|
| Hermes（Windows） | `["%LOCALAPPDATA%\\hermes\\bin\\hermes.exe","chat","-Q","--query-file","{prompt_file}"]` | 已實測。用絕對路徑，工作排程器的 PATH 可能不同 |
| Hermes（Linux） | `["hermes","chat","-Q","-q"]`，`prompt_via: "arg"` | |
| Hermes（API） | `"mode": "api"`、`api_url`、`api_key` | 呼叫 `hermes gateway` 開的 OpenAI 相容端點 |
| Codex CLI | `["codex","exec","--skip-git-repo-check","--sandbox","workspace-write","-o","{answer_file}","-"]`，`prompt_via: "stdin"` | `-` 表示提示詞從 stdin 讀；`-o` 把最後的回答寫進檔案（[官方說明](https://developers.openai.com/codex/noninteractive)）。`--skip-git-repo-check` 讓它在非 git 資料夾也能跑（請用 `codex exec --help` 確認你的版本有這個參數） |
| Antigravity CLI | `["agy","-p"]`，`prompt_via: "arg"` | `-p` 參數來自社群資料，請用 `agy --help` 確認；Windows 上可能卡住，建議先在 Linux 用 |

Windows 注意事項（office-node 已自動處理）：
- npm 裝的 CLI（例如 `codex`）在 Windows 是 `.cmd` 檔，不能直接執行：office-node 會改經 `cmd.exe` 執行，提示詞自動改走 stdin，避免被引號和換行弄壞。
- 呼叫時會設定 `PYTHONUTF8=1`、`NO_COLOR=1`、`TERM=dumb`，回報前也會清掉顏色碼和框線。
- 驗收指令在 Windows 用 `cmd.exe` 執行（先切 UTF-8），在 Linux 用 `/bin/sh`。

用 `office join --kind hermes|codex|antigravity` 加入時，會自動在 `workers` 加一段該平台的預設指令（就是上表的寫法），之後再依需要修改。設定好後用 `office doctor` 檢查：每個執行者都會顯示 token 對應的帳號，以及指令能不能執行（`--version`）。

## 三、當櫃台

### 1. 任何終端機：`office ask`（Windows、Linux 都能用）

設定檔加上 `boss_token`（你的真人帳號 token），然後：

```bash
office ask "整理兩台電腦的磁碟使用量，做成表格"
```

它會開目標（主管自動選 Claude）、把進度訊息印出來、等到結案後印出總結。可加 `--lead claude_b` 指定主管、`--download <目錄>` 自動下載結果檔、`--timeout <分鐘>` 設定最長等待時間。任何能執行指令的 AI，也都能用這個指令當櫃台。

### 2. 支援 MCP 的平台：接 Hub 的 `/mcp`

接上後就有 `office_*` 工具。當櫃台的流程是：`office_new_goal`（`lead` 填 `"auto"`，讓 Claude 當主管）→ 重複呼叫 `office_wait(goal_id)` 直到 `done` 為 `true` → 把 `goal.summary` 回給使用者。Hub 的 MCP 說明會自動告訴它這套流程。

每個平台要用**自己的帳號 token**（先照第一節加帳號）。注意：同一個帳號不要同時當執行者又當櫃台，因為 `office_wait` 和執行者的收訊息用的是同一條佇列。要兩種都用，就開兩個帳號。

| 平台 | 設定檔 | 寫法 |
|---|---|---|
| Claude Code（辦公室 session） | 不用設定 | office 外掛已經提供 `office_*` 工具 |
| Claude Code（桌面版或一般 session） | `office setup-desktop` | 見下面第 3 點；用 claude 帳號會自己當主管 |
| Hermes | `~/.hermes/config.yaml` | `mcp_servers:` 底下加 `office: { url: "http://<Hub>:7070/mcp", headers: { Authorization: "Bearer <token>" } }`，再 `/reload-mcp`（[說明](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)） |
| Codex CLI | `~/.codex/config.toml` | `[mcp_servers.office]`，`url = "http://<Hub>:7070/mcp"`，`bearer_token_env_var = "OFFICE_TOKEN"`，再把 token 放進環境變數 `OFFICE_TOKEN`（[說明](https://developers.openai.com/codex/mcp)） |
| Antigravity CLI | `~/.gemini/config/mcp_config.json` | `"mcpServers": { "office": { "serverUrl": "http://<Hub>:7070/mcp", "headers": { "Authorization": "Bearer <token>" } } }`（遠端伺服器用 `serverUrl`；[說明](https://antigravity.google/docs/cli/mcp)） |

接好後在各平台裡用 `/mcp` 確認 `office` 已連上，並看得到 `office_new_goal`、`office_wait` 等工具。

### 3. Claude Code 桌面版（當主管，直接派工）

桌面版沒辦法載入開發者頻道，收不到「叫醒」通知，但可以**在同一輪裡自己等**：開目標、派工後重複呼叫 `office_wait(goal_id)`，收到回報就審查、改派，全部完成後結案，在對話裡交出成果。Hub 的 MCP 說明和 `/office` skill 都已經寫好這套流程。

設定（在那台電腦執行）：

```bash
office setup-desktop
```

1. 它把 Hub 的 MCP（名稱 `office-desktop`，用 `claude_token` 的 claude 帳號）加進 Claude Code 使用者設定、移除舊的重複設定 `office-hub`，並安裝 `/office` skill。同一台第二個帳號用 `--as <帳號>`。
2. `~/.office/config.json` 加 `"claude_mode": "desktop"`，重開 office-node：桌面版沒有 hooks，改由 office-node 在跑就把這個 Claude 顯示為在線。
3. 重開桌面版，開本機 session，輸入 `/office <目標>`。

限制：
- 等待時那一輪會一直跑；要插話就按停止，之後說「繼續等目標 #N」。
- 別人丟給它的工作（另一台 Claude 派的、Hermes 失敗改派回來的）要等它下次 `office_wait` 才看得到；沒在等的時候會先排著。
- 同一個帳號不要同時開終端機的 `office-claude`，兩邊會搶派工訊息。
- 不要在桌面版的環境變數設 `OFFICE_SESSION=1`（那是終端機頻道模式用的）。
- office 外掛在桌面版用不到（不提供工具、hooks 不動作），留著無害；不再用終端機模式可以 `claude plugin uninstall office@office-local`。

## 四、同一台多個 Claude

Claude Code 桌面版的設定是整台電腦共用的，所以**一台只能有一個桌面版主管**。同一台要多個 Claude，其他的要用終端機頻道模式：

1. 在 Hub 加帳號：`bun run cli add claude_c --name Claude-C --kind claude --machine A`
2. 設定檔加上 `"claude_profiles": { "claude_c": "<token>" }`
3. `office setup-claude --as claude_c`（寫到 `~/.claude/channels/office-claude_c/`）
4. 用 `office-claude claude_c` 啟動（Windows：`office-claude.cmd claude_c`）

每個 Claude 用各自的帳號收派工、呼叫 `office_*` 工具。office-node 的 session 偵測只認得主要那個 Claude；其他 Claude 的在線狀態，靠外掛的連線和 hooks 判斷。

## 五、Windows 與 Linux 的對照

| 項目 | Windows | Linux（含 WSL） |
|---|---|---|
| 安裝 Bun | `winget install Oven-sh.Bun` | `curl -fsSL https://bun.sh/install \| bash` |
| 啟動 Hub | `scripts\windows\start-hub.cmd`（設定寫在 `hub.env.cmd`） | `scripts/linux/start-hub.sh`（設定寫在 `hub.env`） |
| 啟動 office-node | `scripts\windows\start-office-node.cmd` | `scripts/linux/start-office-node.sh` |
| 開機常駐 | `scripts\windows\install-tasks.ps1 -Hub -Node`（工作排程器） | `scripts/linux/install-services.sh --hub --node`（systemd 使用者服務） |
| office 指令 | `node\office.cmd`（把 `node` 資料夾加進 PATH） | `node/office`（同上） |
| Claude 桌面版主管 | `office setup-desktop` | —（桌面版沒有 Linux 版） |
| 終端機頻道模式 | `node\office-claude.cmd [帳號]` | `node/office-claude [帳號]` |
| 終端機模式的 session 偵測 | PowerShell `Get-CimInstance` | `pgrep` |
| 驗收指令 | `cmd.exe`（可呼叫 PowerShell） | `/bin/sh` |
